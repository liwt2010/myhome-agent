# 数据保护影响评估（DPIA / DPIA）

> myhome-agent 家庭智能体 v1.0 GDPR DPIA 完整文档。
> 评估 4 个高风险数据流：摄像头 / LLM 兜底 / 远程控制 / 视觉事件。
> 评估方法：CNIL / GDPR Article 35 模板 + EDPB 指南。

## 1. 评估范围

**系统**：myhome-agent v0.7（家庭智能体）
**控制者**：家庭管理员（admin member_id）
**DPO**：家庭自治（v0.7 暂不强制设 DPO，单实例 ≤3 家庭不要求）
**评估日期**：2026-08-03
**评估人**：架构组 + 用户代表

## 2. 数据流总览

```
摄像头 ──→ 视觉管线 ──→ 规则引擎 ──→ 通知路由 ──→ 子女/管理员
                 ↓              ↓
              snapshot      audit log
                 ↓
              Fernet 加密
                 ↓
              30 天后清理

LLM 兜底 ──→ DeepSeek 云端 ──→ 脱敏（redactor）──→ 返回结构化建议
                                          ↑
                                  凭证/隐私/敏感字段全脱敏

远程控制 ──→ 二次确认 ──→ capability 校验 ──→ 设备执行
              ↑                            ↓
              撤销窗（30s / 60s 老人）    反馈环

视觉事件 ──→ evidence_snapshot ──→ 30 天清理
              ↑
        household_id 强制隔离
```

## 3. 风险评估

### 3.1 摄像头 / 视觉管线

| 维度 | 评估 |
|------|------|
| **数据类别** | 原始视频流（v0.3 不存盘）+ 视觉事件结构化记录 + snapshot 截图 |
| **敏感度** | 🔴 高（含人脸、行为、可识别家庭成员）|
| **规模** | 单家庭 ≤16 路摄像头（v0.5 限）|
| **流向** | 摄像头（本地 LAN）→ 视觉管线（NAS 本地）→ 规则引擎 → 通知（本地）/ 上云（仅 DeepSeek-Vision 显式调用）|
| **法律基础** | 家庭成员共同同意（v0.6 `members.consent_flags.vision`）|
| **风险** | 摄像头被远程入侵 → 隐私泄漏 |
| **缓解** | • 选 ONVIF / RTSP 型号（隐私红线 v0.3）<br>• 不允许云端流转<br>• 30 天自动清理<br>• snapshot Fernet 加密<br>• admin 单独无法开启摄像头 |
| **残留风险** | 🟡 中（远程攻击 → 家庭同意书）|

### 3.2 LLM 兜底（DeepSeek 云端）

| 维度 | 评估 |
|------|------|
| **数据类别** | 规则触发证据 + 家庭成员画像 + 历史 |
| **敏感度** | 🟠 中（含行为模式、习惯数据）|
| **规模** | ≤10 次/天/家（v0.5 动态配额）|
| **流向** | 家庭 → 脱敏（§5.11 redactor）→ DeepSeek 云端 → 返回结构化 JSON |
| **法律基础** | 显式同意（admin 启用 v0.5 LLM 兜底开关）|
| **风险** | 脱敏漏掉敏感字段 → 云端泄漏 |
| **缓解** | • §5.11 redactor 上线前必测<br>• 调用前白名单字段<br>• 凭证/token/密码黑名单<br>• DeepSeek 不存日志（按服务条款）<br>• 用户可关闭 LLM 兜底（降级到 §42 规则） |
| **残留风险** | 🟢 低（量化后 < 5%）|

### 3.3 远程控制（TG / PWA）

| 维度 | 评估 |
|------|------|
| **数据类别** | 控制指令 + 设备反馈 + 撤销栈 |
| **敏感度** | 🟠 中（指令本身不敏感，但动作可能不可逆）|
| **规模** | 不限次，但 irreversible 强制 L1 |
| **流向** | 子女/TG → 二次确认 → capability 校验 → 设备执行 |
| **法律基础** | 家庭成员 + 子女的看护关系 |
| **风险** | 老人 TG 账号被冒用 → 误开锁 / 误关阀 |
| **缓解** | • TG /bind per-member 绑定<br>• irreversible capability 强制 L1<br>• 撤销窗 30s/60s<br>• 反馈环 状态校正<br>• 异常告警（v0.6 治理仪表盘）|
| **残留风险** | 🟡 中（账号安全 → 2FA 留 v1.0）|

### 3.4 视觉事件（结构化记录）

| 维度 | 评估 |
|------|------|
| **数据类别** | bounding box + 类别 + 置信度 + snapshot 路径 |
| **敏感度** | 🟠 中（不存原图但有结构化描述）|
| **规模** | ≤ 1 万条/家/月 |
| **流向** | 摄像头 → 视觉管线 → vision_events 表 → 30 天清理 |
| **法律基础** | 家庭共同同意（开摄像头即同意）|
| **风险** | 越权访问 events 表 |
| **缓解** | • household_id 强制隔离（§36.6）<br>• 30 天自动清理<br>• Fernet 加密 snapshot 路径<br>• GDPR 删除时级联清 |
| **残留风险** | 🟢 低 |

## 4. GDPR 7 项原则符合性

| 原则 | 符合方式 |
|------|---------|
| **1. 合法、公平、透明** | 家庭共同同意 + admin 强制 PWA 同意 |
| **2. 目的限制** | 数据仅用于"家庭照护"（明示），不开商业 |
| **3. 数据最小化** | §5.11 redactor + capability 最小化 |
| **4. 准确性** | 成员画像可编辑；摄像头检测有置信度 |
| **5. 存储限制** | 30 天自动清理（vision / readings / events）|
| **6. 完整与保密** | household_id 隔离 + Fernet 加密 |
| **7. 问责** | 审计日志 + 治理仪表盘 + DPIA 文档 |

## 5. 数据主体权利（v0.7 落实）

| 权利 | v0.7 实现 |
|------|----------|
| **被遗忘权** | §43.3 删 member 10 步级联流程 |
| **数据可携** | `myhome-agent export --member=X` 输出 JSON |
| **访问权** | 治理仪表盘 + `/api/members/{id}/data` |
| **更正权** | PWA `/settings/members` 编辑 |
| **限制处理** | `members.consent_flags` 单字段关闭 |
| **反对权** | LLM 兜底 / 摄像头 / 远程控制 独立开关 |
| **不受自动决策** | L1 强制 confirm（v0.5 治理）|

## 6. 数据保护官（DPO）

**v0.7 状态**：**不强制**（单实例 ≤3 家庭，GDPR Article 37 不要求 DPO）

**v1.0 计划**：
- 商业化版本（含 SaaS 多家庭）必须设 DPO
- 开源家庭版仍可选
- 公共规则市场必须有 DPO 团队

## 12. v1.0 升级版（商业化场景）

> v0.7 DPIA 评估单实例家庭版。v1.0 加 4 个商业化特有风险：

### 12.1 SaaS 多家庭托管

| 维度 | 评估 |
|------|------|
| **数据规模** | ≥100 家庭 / 服务器 / 50+ 摄像头/家 |
| **跨境传输** | 国际家庭数据 → 主数据中心（GDPR Article 44）|
| **法律基础** | 家庭共同同意 + 商业合同 DPA |
| **新风险** | 🔴 数据驻留 + 第三方访问控制 + DPO 必设 |
| **缓解** | • 区域化数据中心（EU/Asia/America 分区）<br>• SCC 标准合同条款<br>• 第三方 DPA 协议（processor 协议） |
| **残留** | 🟡 中（DPIA 必填 + DPO 双签）|

### 12.2 第三方集成（API 合作伙伴）

| 集成 | 数据流向 | DPIA 风险 |
|------|---------|-----------|
| 医院 API | 健康数据 ↔ 第三方 | 🔴 高（HIPAA + GDPR）|
| 维修公司 API | 设备 token ↔ 第三方 | 🟡 中 |
| 教育 API | 儿童数据 ↔ 第三方 | 🔴 高（COPPA + GDPR）|

**强制要求**：第三方 DPIA + DPA + 安全审计

### 12.3 公共规则市场（v1.0 §63）

| 维度 | 评估 |
|------|------|
| **数据流** | 模板上传（作者 → 市场）→ DPIA 检查 → 上架 → 用户下载 |
| **法律基础** | 作者同意书（CC-BY-SA-4.0）+ DPO 双审 |
| **风险** | 🔴 safety 模板被滥用 → 家庭事故 |
| **缓解** | • §55 5 项不变量<br>• DPO 双审 safety<br>• 评论 ≥ 5 + < 3 星自动下架<br>• 强制 enabled=0 |
| **残留** | 🟡 中 |

### 12.4 数据驻留策略

| 地区 | 主数据中心 | 备份 | 加密 |
|------|-----------|------|------|
| EU | 法兰克福 | 阿姆斯特丹 | Fernet + HSM (v1.0) |
| Asia | 新加坡 | 香港 | Fernet |
| America | 弗吉尼亚 | 俄勒冈 | Fernet |

**家庭可选**：`household.data_residency='eu'|'asia'|'america'`。

### 12.5 DPIA 自动化（v1.0）

```

   ↓
自动触发 DPIA 检查：
  - 数据流图自动生成（matplotlib）

  - DPO 必审触发（safety 类）
   ↓
DPIA 报告自动存档
   ↓
上架
```
