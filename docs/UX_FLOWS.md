### 1.6 中断恢复

每次 Step 完成时**写入 onboarding_state** 表（`last_step`、`completed_at`）：

```sql
CREATE TABLE onboarding_state (
  step INTEGER PRIMARY KEY,   -- 0..4
  completed_at TEXT
);
```

下次打开 PWA 自动跳到 `last_step + 1`，除非全部 `completed_at` 都非空。

## 2. 系统状态灯（§16）

### 2.1 实现位置

**PWA 顶部** global header 右上角常驻 pill：

```
[ 🟢 健康 ]            正常态
[ 🟡 降级 ⚠ ]         黄色 + 警告图标
[ 🔴 异常 ⚠ ]         红色 + 警告图标
[ ⚫ 离线 ]           探不到后端
```

点 pill 打开 `StatusDrawer`：

```
┌─────────────────────────┐
│  系统状态                  │
├─────────────────────────┤
│ 🟢 设备采集      正常     │

│   [ 重试 ] [ 上报 ]      │

│ 最近一次全检查: 2 分钟前  │
```

## 3. 成员配对流程（§19）

### 3.1 管理员 PWA 动作

**位置**：`/settings/members` 右上角"+ 邀请家人"

弹窗：

```
┌──────────────────────────────────┐
│  邀请家人                          │
│                                  │
│  姓名 [_______]                  │
│  角色 [adult ▾]                  │
│  渠道  ⦿ Telegram   ◯ 微信        │
│  时长 [24 小时 ▾]（访客）         │
│                                  │
│  生成 [ 配对链接 ]                │
│                                  │
│  ✓ 已生成                        │
│  🔗 https://home.local/pair/xx   │
│  ▢ QR code                       │
│  5 分钟内有效                     │
│  [ 复制 ] [ 分享 ]  [ 撤销 ]    │
└──────────────────────────────────┘
```

### 3.2 家人侧动作（以 TG 为例）

**群聊或私聊**：
- 收到系统"邀请"消息（admin 转发）
- 输入 `/pair abc1234`
- Bot 回"你被 xxx 邀请加入 yyy 家庭，角色 adult，同意吗？[是/否]"
- 同意 → 绑定完成，bot 提示"绑定成功，你现在可以对话了"

**QR code 走 PWA**：扫 → PWA `/pair/abc1234` 确认页 → 点击确认 → 进入 dashboard。

### 3.3 家庭多渠道一个人

member.channels 可以同时有多个：
- TG: `{user_id: 1234, paired_at: "...", role: adult}`  
- 微信: `{openid: "xyz", paired_at: "...", role: adult}`

**规则**：同一个人从不同渠道来的请求视为不同 session，dev 期间可视为同 member；统一 authz 但不合并 chat_history。

### 3.4 撤销

admin 在成员列表点"解除绑定"→ 系统弹"确定解除绑定？此成员将无法使用 myhome-agent" → 二次确认 → `channels.<channel>.<user_id>` 字段清空。

## 4. 场景执行中（PWA 端 vs chat 端）

### 4.1 PWA 执行场景

**位置**：`/scenes` 详情页（执行按钮）

执行中状态：

```
┌─────────────────────────────┐
│  睡觉模式 [执行中...]         │
│  ▓▓▓▓▓▓▓▓▓▓ 4/4 (步骤 3)    │
│                              │
│  ✓ 关客厅灯          1.2s    │
│  ✓ 关客厅窗帘        0.8s    │
│  ⏳ 开卧室夜灯...              │
│  ○ 关闭所有空调               │
│                              │
│  策略: ask_user              │
│                              │
│  [ 取消 ]  [ 暂停 ]           │
└─────────────────────────────┘
```

**失败中（ask_user）状态**：

```
┌─────────────────────────────┐
│  睡觉模式 [暂停 - 等待确认]   │
│                              │
│  ✓ 关客厅灯                  │
│  ✗ 关客厅窗帘（拒绝 / 离线）  │
│  ？                          │
│                              │
│  "客厅窗帘关不了，怎么做？"    │
│                              │
│  [ 重试 ] [ 跳过 ] [ 回滚全部 ] │
└─────────────────────────────┘
```

### 4.2 chat 端执行场景

用户：`开睡觉模式` → agent 回：

> 我来跑 `睡觉模式`（dry-run 报告：4 步全可执行）。开始执行。
>
> ✓ 关客厅灯（1.2s）
> ✓ 关客厅窗帘（0.8s）
> ⏳ 开卧室夜灯...
>
> 报错：卧室夜灯拒绝响应（已离线）。策略是 ask_user，您想：
> - 重试
> - 跳过
> - 回滚全部（关客厅灯和窗帘都要撤）
>
> 您的选择？

**用户在当前对话窗口回复关键字**：

- `重试` / `retry` → 重试当前步
- `跳过` / `skip` → 标记 done，继续下一步
- `回滚` / `rollback` → 全部回滚

## 6. 成员切换 / 多成员会话

### 6.1 PWA 默认行为

首装者（admin）默认显示全功能视图。其他成员通过显式"切换为我"按钮切到自己的视图。

```
顶栏 → [家庭] [我] [管理]   ← admin 视角
顶栏 → [家庭]                ← non-admin 视角
```

"我"页面 = 我的在场状态、我的设备权限内的视图、自己 chat 历史。

### 6.2 成员切换时的视觉差异

| 模块 | admin | adult | child | guest |
|------|-------|-------|-------|-------|
| 顶部 | 完整 | 完整 | 简化 | 简化 |
| 仪表盘 | 全设备 | 全设备 | 仅自己房间 | 仅常用设备 |
| 设备面板 | 全设备 | 全设备 | 仅自己关联 + light | 仅 light |
| 告警中心 | 全 | 全 | 受限 | 无 |
| 设置 | 全 | 仅偏好 | 仅昵称 | 无 |

## 7. 错误与降级 UI 模式

### 7.1 设备控制失败

```
┌────────────────────────────┐
│  关客厅灯                    │
│  ✗ 没控制上                  │
│  设备无响应（已离线 5 分钟）  │
│  [ 重试 ] [ 取消 ]           │
└────────────────────────────┘
```

**重试逻辑**：内部自动已重试 1/2/5s 三次（§5.6b）。用户按钮重试是手动第 4 次。

### 7.2 网络断开

顶栏黄色 banner：`⚠ 网络断了，部分功能停用。[ 查看详情 ]`

模态详情显示哪些功能受影响 + 预计恢复策略（auto reconnect）。

### 7.3 LLM 故障

虽然对话质量下降，但仍能用 chat 面板——顶栏黄色 chip 显示"AI 部分能力受限"

**位置**：`/audit`

```
┌─────────────────────────────────────┐
│  自主行为记录                          │
│  [全部 ▾] [24h] [7d] [30d]          │
├─────────────────────────────────────┤
│  🕐 2 小时前                         │
│  系统自动开"离家"模式                 │
│  触发: 全家外出超过 2 小时           │
│  ⓘ 证据: 5 台设备同时离线事件链      │
│  ⟳ 关闭了: 窗帘×2 空调×3 灯×5      │
│  [ 👍 同意 ]  [ 👎 不当 ]  [ 🔍 链 ] │
├─────────────────────────────────────┤
│  🕐 昨天 8:00                         │
│  早间播报推送                          │
│  触发: 定时任务                        │
│  ...
└─────────────────────────────────────┘
```

点 🔍 链 跳到 `/audit/<autonomous_id>` 详情页：

```
┌─────────────────────────────────────┐
│  Autonomous #ad12...                  │
│  ────────────────────────────────── │
│  触发: 全家外出超 2h                  │
│  证据链:                               │
│   - 12:34  灯全关 (events id=123)      │
│   - 12:35  窗帘半开 (events id=125)    │
│   - 12:40  WiFi 探测全家人离网          │
│  决策:                                  │
│   → 全家出门 = 离家场景                │
│  动作:                                  │
│   - 关窗帘 × 2                         │
│   - 关闭空调 × 3                       │
│   - 关闭所有灯 × 5                     │
│  反馈（影响此决策后续行为）：           │
│   [ 👍 同意 ]  [ 👎 下次别这样 ]       │
└─────────────────────────────────────┘
```

**用户点 👎 后的语义**：

- 把 `pattern_history.{trigger_signature}` 的 `user_rejected=true`
- 该决策不再被自动执行（autonomous_id 入黑名单 90 天）
- 自动给 chat "理解，下次不会自动做了"
